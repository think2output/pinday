# PinDay 기획서 — 부산을 이야기로 여행하는 AI 도슨트 플래너

Oct 24, 2026 · @우현

## 1. 한눈에 보기

PinDay는 부산 여행을 계획하는 사람이 지도에서 장소를 모아 날짜별 일정을 만들고, 그 장소의 역사와 이야기를 근거 있는 AI 도슨트로 읽고 듣는 부산 특화 여행 플래너다.

| 항목 | 내용 |
| --- | --- |
| 한 줄 정의 | 부산을 이야기로 여행하는 AI 도슨트 플래너 |
| 목표 | 주말 동안 실사용 가능한 반응형 웹 서비스로 오픈 (팀 프로젝트의 완성형 시연 버전) |
| 타깃 | 부산 여행을 계획 중인 사람. 첫 화면은 부산을 잘 모르는 사람도 막히지 않게 설계 |
| 해결할 문제 | 여행지 정보·지도·일정·장소 설명이 여러 앱에 흩어져 있고, "이곳이 왜 의미 있는지"를 믿을 만하게 알려주는 곳이 없다 |
| 차별점 | 부산 특화 + 근거 자료 안에서만 해설하는 AI 도슨트(역사·이야기, 현장 관람 포인트, 듣기) |
| 포지션 | AI가 코스를 대신 짜주는 서비스가 아니라, 내가 고르고 가서 더 깊이 즐기게 돕는 서비스 |
| 계정 | 없음. 모든 여행 정보는 사용자 브라우저에 저장 |
| 원칙 | 확인되지 않은 정보는 만들지 않는다. 근거가 없으면 없다고 표시한다 |

## 2. 경쟁 서비스와 포지션

두 서비스가 취향 진단·구별 탐색·AI 코스·일정을 이미 제공하므로, PinDay는 둘 다 하지 않는 근거 기반 역사 해설(AI 도슨트)을 중심에 둔다.

| 서비스 | 형태 | 주요 기능 | 데이터 | PinDay와 겹치는 점 |
| --- | --- | --- | --- | --- |
| [가치GO](https://gachigo.kr/) | 앱 | 여행 DNA 16유형 진단, AI 테마 코스, AI 여행친구 채팅, 동행 매칭 | 한국관광공사 OpenAPI, 부산관광아카이브, 카카오맵 | 취향 진단, AI 추천 |
| [부산어디?](https://busan-where.com/) | 웹·안드로이드 | 16개 구·군별 탐색, 약 2,700곳(관광지·맛집·숙소), AI 코스, 축제, 11개 언어 | 부산시 공공데이터, 네이버, 한국관광공사 | 구별 지역 선택, 장소 탐색 |

- 데이터 양으로는 경쟁하지 않는다. 이야기할 거리가 있는 장소 중심으로 깊게 간다.
- 두 서비스의 AI 채팅은 일정·맛집 비서에 가깝고, 근거를 보여주는 역사 해설은 확인되지 않았다(2026-10-24 기준 사이트 확인).

## 3. 범위

주말 버전은 9개 화면(홈·랜덤 뽑기 포함)을 모두 넣되, 데이터는 관광지만 다루고 계정·공유·맛집은 다음 버전으로 미룬다.

| 구분 | 내용 |
| --- | --- |
| 완성도 최우선 | 홈, 어디 갈까?, 언제 갈까?, AI 도슨트(목록·상세) |
| 기본 동작 | 취향 테스트, 랜덤 뽑기, 어떻게 갈까?, 날씨 대안 |
| 주말 버전 제외 (다음 버전) | 동행과 일정 공유(1순위), 맛집·카페, 도슨트 물어보기(질문 답변), 계정·여러 여행 관리, 다국어 |
| 다음 버전 후보 | 공유 링크로 일정 함께 보기, 성공 지표 측정 도구, 음성 파일 미리 만들기 |

## 4. 정보 구조와 화면 흐름

기본 흐름은 홈 → 어디 갈까? → 언제 갈까? → 어떻게 갈까? / 날씨 대안이고, AI 도슨트는 모든 화면의 장소에서 들어갈 수 있다.

**상단 메뉴**: 홈 · 어디 갈까? · 언제 갈까? · 어떻게 갈까? · 날씨 대안 · AI 도슨트 + 오른쪽 "내 여행" 버튼. 휴대폰은 옆으로 밀어 보는 한 줄 메뉴.

| 화면 | 주소(제안) | 들어오는 곳 | 나가는 곳 |
| --- | --- | --- | --- |
| 홈 (랜덤 뽑기 포함) | / | 메뉴 | 어디 갈까?(시작하기), 도슨트 상세(이야기 카드), 도슨트 목록(전체 보기), 취향 테스트 |
| 취향 테스트 | /taste | 홈, 어디 갈까?(테스트 권유) | 어디 갈까?(취향순), 도슨트 상세 |
| 어디 갈까? | /explore | 홈, 메뉴, 취향 테스트 | 도슨트 상세(이야기 보기), 언제 갈까?(날짜에 배치하기) |
| 언제 갈까? | /schedule | 어디 갈까?, 메뉴, 내 여행 | 어떻게 갈까?, 날씨 대안, 도슨트 상세 |
| 어떻게 갈까? | /route | 언제 갈까?, 메뉴 | 카카오맵(외부) |
| 날씨 대안 | /weather | 언제 갈까?, 메뉴 | 도슨트 상세 |
| AI 도슨트 목록 | /docent | 메뉴, 홈 | 도슨트 상세 |
| AI 도슨트 상세 | /docent/{장소id} | 모든 장소 카드 | 근처 장소 상세, 카카오맵 길찾기, 일차 고르기 창 |

**이동 규칙**

1. 헤더 "내 여행"과 홈 "이어서 계획하기": 후보함이 비었으면 어디 갈까?, 하나라도 있으면 언제 갈까?.
2. 도슨트 상세의 뒤로가기: 들어온 화면으로 돌아간다(고정 문구 금지).
3. 메뉴로 바로 들어와 지역·기간이 없으면 "부산 전체 + 내일부터 2박 3일"로 자동 시작하고 "자동으로 정했어요"를 표시한다.
4. 조건 바꾸기는 화면을 떠나지 않고 그 자리의 작은 창에서 바꾼다.

## 5. 공통 데이터: 내 여행 정보

모든 화면은 브라우저에 저장된 하나의 "내 여행 정보"를 함께 읽고 쓴다. 쓰기가 몰리는 후보함과 일정을 가장 먼저, 가장 튼튼하게 만든다.

| 항목 | 내용 | 규칙 |
| --- | --- | --- |
| 지역 | 고른 구·군 목록 (없으면 부산 전체) | 저장 값은 시·도 전체 이름 기준(예: 부산광역시, 부산광역시 수영구). 화면 표시는 "수영구"처럼 짧게 |
| 기간 | 출발일, 도착일 | 지난 날짜 불가, 최대 14일. 기본값 내일부터 2박 3일 |
| 취향 유형 | 취향 테스트 결과 4종 중 하나 | 테스트를 안 했으면 비어 있음 |
| 후보함 | 담은 장소 id 목록 | 일정에 넣어도 후보함에 남는다 |
| 일정 | 날짜별 장소 id와 순서 | 같은 장소는 하루에만. 후보함에 없는 장소를 넣으면 후보함에도 추가 |

**화면별 읽기·쓰기**

| 화면 | 지역·기간 | 취향 | 후보함 | 일정 |
| --- | --- | --- | --- | --- |
| 홈 | 쓰기·읽기 | - | 읽기 | 읽기 |
| 랜덤 뽑기 | 읽기 | - | 쓰기 | - |
| 취향 테스트 | - | 쓰기 | - | - |
| 어디 갈까? | 읽기·쓰기 | 읽기 | 읽기·쓰기 | - |
| 언제 갈까? | 읽기 | - | 읽기 | 쓰기 |
| 어떻게 갈까? | - | - | - | 읽기 |
| 날씨 대안 | 읽기 | - | - | 쓰기(장소 교체) |
| 도슨트 목록 | 읽기 | - | 읽기 | 읽기 |
| 도슨트 상세 | - | - | 쓰기 | 쓰기 |

**규칙**

- 자동으로 정한 지역·기간은 표시만 하고, 사용자가 장소를 처음 담는 순간 저장한다.
- 기간을 줄이면 사라지는 날짜의 장소는 "아직 날짜 없는 곳"으로 옮기고 "3일차 장소 2곳이 날짜 없는 곳으로 옮겨졌어요"를 알린다. 지역을 바꿔도 담은 장소는 그대로 둔다.
- **여행 초기화**: 지역·기간, 후보함, 일정, 취향 유형을 모두 지운다. 진입점은 홈 내 여행 카드 ⋯ 메뉴와 조건 바꾸기 창 맨 아래 두 곳. 확인 창에 지워질 내용을 숫자로 보여주고(예: 후보 6곳, 일정 3곳), 지운 뒤 몇 초간 되돌리기를 띄운다.
- 한 곳에서 바꾸면 모든 화면에 바로 반영된다. 예: 도슨트 상세에서 후보함에 담으면 어디 갈까? 핀이 ✓, 홈 내 여행 카드 점이 하나 켜지고, 언제 갈까?의 날짜 없는 곳에 나타난다.

## 6. 화면별 상세 기획

각 화면은 목적, 구성(위에서 아래 순서), 동작 규칙으로 정리한다. 와이어프레임은 14장 링크 참고.

### 6-1. 홈

- 목적: 처음 온 사람은 어디·언제만 정하고 바로 시작, 다시 온 사람은 하던 계획을 이어가기.
- 구성: 메뉴바 → 첫 문구 → 여행 조건(블록형 지도 + 선택한 구 태그 + 기간 + 시작 버튼) → 지도와 연결된 이야기 카드 → 취향 테스트 / 랜덤 뽑기 상자 → 출처 표기. 다시 온 사람은 맨 위에 내 여행 카드.
- 지도: 부산 16곳(15구 + 기장군)을 비슷한 크기의 블록으로 위치만 맞춘 일러스트. 실제 경계 지도는 중구·동구가 너무 작아 휴대폰에서 누를 수 없어 쓰지 않는다. 칸에 구 이름과 대표 명소, 마우스를 올리면 관광지 수. 0곳인 구는 흐리게, 선택 불가. 여러 곳 선택 가능, 선택한 구는 "수영구 ✕" 태그로 표시.
- 시작 버튼: 선택이 없으면 "부산 전체로 시작하기", 있으면 "선택한 N곳으로 시작하기".
- 이야기 카드: 선택이 없으면 "이번 주 부산 이야기"(직접 고른 고정 목록), 구를 고르면 "수영구의 이야기"로 바뀐다. 카드 = 사진, 해설 첫 문장, 현장 포인트 1개, 근거 출처, 이야기 전체 보기. 사용 기록이 없는 오픈 초기에는 "인기" 표시 금지.
- 내 여행 카드: 모은 핀(점), 기간, 후보 수·일정 수, 날짜별 일정 막대, 이어서 계획하기, ⋯ 메뉴(새 여행 시작하기).
- 휴대폰: 지도 칸 44px 이상, 이야기 카드는 옆으로 넘기기.

### 6-2. 랜덤 뽑기 (홈 안)

- 슬롯처럼 장소 이름이 바뀌다 멈추는 연출(약 1.5초) → 결과 카드(사진, 구·분류, 해설 첫 문장).
- 버튼: ▶ 이야기 듣기 → 도슨트 상세(첫 번째 버튼), 후보함 담기, 다시 뽑기.
- 기회 3번, 새로고침하면 초기화. 다 쓰면 "뽑기 끝! 후보함을 확인해보세요".
- 뽑는 범위: 홈에서 고른 구(없으면 부산 전체) 중 이야기 있는 장소. 같은 장소 연속 금지. 움직임 줄이기 설정이면 연출 없이 결과.

### 6-3. 취향 테스트

- 부산에서의 하루를 따라가는 5문항, 보기는 그림 카드 4장. 진행 표시: 아침 → 오후 → 해 질 녘 → 하루 정리 → 귀가. 이전, 건너뛰기 가능.

| 때 | 장면 | 질문 | 보기 (골목 / 바다 / 역사 / 활동) |
| --- | --- | --- | --- |
| 아침 | 부산역에 막 내렸어요. | 제일 먼저 향하는 곳은? | 언덕 위 골목 마을 / 바다가 보이는 카페 / 오래된 성곽길 / 케이블카 타는 곳 |
| 오후 | 점심을 든든히 먹었어요. | 끌리는 오후는? | 골목 사이 작은 가게 구경 / 해변 따라 산책 / 박물관에서 이야기 듣기 / 해안 절벽 산책로 |
| 해 질 녘 | 하늘이 붉어지기 시작해요. | 사진 한 장을 남긴다면? | 알록달록 지붕들 / 노을 지는 바다와 다리 / 고즈넉한 절 마당 / 높은 전망대 위 야경 |
| 하루 정리 | 숙소 가는 길, 하루를 돌아보니 | 오늘 몇 곳을 들렀나요? | 2곳을 깊게 / 3곳, 쉬엄쉬엄 / 4곳 알차게 / 셀 수 없이 많이 |
| 귀가 | 침대에 누워 휴대폰을 켰어요. | 친구에게 보내는 한 줄은? | "이 동네 진짜 정 있다" / "바다 보니까 다 풀린다" / "이런 역사가 있는 줄 몰랐어" / "오늘 다리 터질 뻔" |

| 결과 유형 | 한 줄 설명 | 어디 갈까?에서 위로 올리는 분류(초안) |
| --- | --- | --- |
| 이바구길 골목 산책자 (이바구 = 부산 말로 이야기) | 언덕 위 골목을 천천히 걸으며 동네의 이야기를 발견 | 문화마을 · 거리 · 공원 |
| 광안리 노을 감상가 | 바다를 곁에 두고 쉬어가는 여행 | 해수욕장 · 공원 |
| 동래성 시간 여행자 | 장소의 역사를 알고 볼 때 더 즐거운 여행 | 유적 · 사찰 · 박물관 |
| 태종대 파도 탐험가 | 절벽 산책로, 전망대, 탈 것까지 꽉 채우는 여행 | 전망 · 체험 · 공원 |

- 결과 계산: 가장 많이 고른 유형, 동점이면 마지막 문항에서 고른 유형.
- 결과 화면: 캐릭터 그림, 이름, 설명, 키워드 → ▶ 첫 이야기 듣기 → 어울리는 이야기 3편 → 이 취향으로 장소 보기(어디 갈까?) / 다시 하기.
- 그림 24장 필요(보기 20 + 캐릭터 4). 그림이 늦으면 글자 카드로 먼저 열고 나중에 교체할 수 있게 만든다.

### 6-4. 어디 갈까?

- 구성: 여행 조건 줄(그 자리에서 바꾸기) → 분류 버튼 + ▶ 이야기 있는 곳만 → 장소 목록 · 카카오 지도 · 후보함.
- 지도와 목록 연동: 지도를 움직이면 보이는 범위의 장소만 목록에, 목록을 누르면 지도가 그 핀으로. 장소가 많으면 묶음 핀.
- 핀 표시: ▶ 이야기 있음, ✓ 후보함에 담김.
- 장소 미리보기 카드: 사진, 이름, 분류, 해설 첫 문장, 듣기 가능 표시, 후보함 담기, 이야기 보기.
- 정렬: 내 취향순(유형별 분류 규칙, 카드에 "내 취향과 잘 맞아요 · 골목 산책"처럼 이유 표시) / 이름순. 테스트를 안 했으면 이름순 + 테스트 권유.
- 관광지만 표시(맛집·카페는 다음 버전).
- 배치: 데스크톱 목록·지도·후보함 3단, 휴대폰은 지도 + 아래서 끌어올리는 목록 서랍 + 하단 "후보 N곳 · 날짜에 배치하기" 막대. 핀을 누르면 서랍 대신 미리보기 카드.

### 6-5. 언제 갈까?

- 화면은 네 덩어리만: 날짜 탭 → 그날 일정 → 아직 날짜 없는 곳 / 오른쪽 그날 지도.
- 날짜 없는 곳의 "+ N일차에 넣기"는 지금 보는 날에 바로 넣는다(고르는 창 없음).
- 장소마다 버튼은 ⋯ 하나: 이야기 보기 / 다른 날로 옮기기 / 일정에서 빼기. 순서는 ⋮⋮ 끌어서 바꾸기(키보드로도 가능해야 함).
- 지도: 그날 장소를 순서 번호와 점선으로 연결. 실제 경로는 어떻게 갈까?.
- 이동 확인·날씨 확인 버튼은 지도 아래(휴대폰은 하단 고정) 한 곳.
- 비 예보가 있는 날은 날짜 탭에 ☂ 표시.

### 6-6. 어떻게 갈까?

- 날짜 탭 → 그날 경로 지도 → 장소 사이 구간 카드 → 이동 합계.
- 구간마다 대중교통 / 자동차 / 도보 선택. 대중교통·도보 = 카카오맵 API(2026-07 추가된 경로 조회), 자동차 = 카카오모빌리티 길찾기. 모든 구간에 "카카오맵에서 열기".
- 같은 구간 결과는 저장해 다시 쓴다. 장소가 하나뿐인 날은 "이동할 구간이 없어요".

### 6-7. 날씨 대안

- 날짜별 날씨 카드(맑음 / 비 / 예보 전) → 고른 날의 일정 → 야외 장소마다 근처 실내 대안 2\~3곳(이야기 있는 곳 우선).
- 알림은 자동, 바꾸기는 직접: 일정은 "이 장소로 바꾸기"를 눌러야만 바뀌고, 날짜와 순서는 유지. 바꾼 장소에는 "실내 · 바꾼 장소" + 되돌리기.
- 예보가 아직 없는 날은 "예보 전".

### 6-8. AI 도슨트 목록

- 제목 → 내 여행 장소의 이야기(후보함·일정, 없으면 숨김) → 이번 주 부산 이야기 → 모든 이야기 둘러보기(이름 검색, 구 버튼 한 줄, 분류 버튼, 카드 목록).
- 홈에서 고른 구가 있으면 미리 선택된 채로 열린다. 결과가 없으면 "이 조건의 이야기가 아직 없어요" + 조건 초기화.
- 카드에 "▶ 듣기 가능", 근거가 부족한 장소는 "소개만 있어요"로 구분.

### 6-9. AI 도슨트 상세

- 사진(넘겨보기, 출처·공공누리 유형 표기) → 장소 이름·구·분류 → 듣기 막대 → 한 줄 요약 → 역사와 문화 / 동네의 특징 / 방문 전 알아두기 → 현장 관람 포인트 2\~3개 → 근거 자료 목록 → 근처에 이런 곳도 있어요 → 최근 소식.
- 문장 끝 근거 번호를 누르면 원문이 바로 아래 펼쳐진다. 근거가 없는 부분은 "근거 자료에 관련 내용이 없어요". 현장 포인트에 근거가 없으면 영역을 숨긴다.
- 듣기: 한 줄 요약 + 이야기 세 부분 + 현장 포인트만 읽는다. 지금 읽는 부분 강조, 이전·다음 이동. 근처 장소와 최근 소식은 글로만.
- 근처 장소: 실제 좌표로 계산한 직선거리("약 800m")와 한 줄 소개.
- 최근 소식: 부산 지역 언론의 최근 6개월 기사 제목·출처·날짜만, 누르면 원문. 없으면 "최근 6개월 동안 관련 소식이 없어요". 기사 요약은 하지 않는다.
- 행동: 후보함에 담기, 일정에 넣기(일차 고르기 창: 각 날의 현재 장소 수 표시, 이미 있는 날은 막힘), 지도에서 보기, 카카오맵 길찾기. 휴대폰은 하단 고정.

## 7. 빈 상태·오류·예외 처리

원칙: 되는 부분은 그대로 보여주고, 안 되는 부분만 이유와 다음 행동(다시 시도, 다른 화면으로)을 안내한다.

| 상황 | 화면 | 보여줄 것 |
| --- | --- | --- |
| 지역·기간 없음 | 어디 갈까?, 날씨 대안 등 | 부산 전체 + 내일부터 2박 3일 자동, "자동으로 정했어요 · 바꾸기" |
| 후보함 비어 있음 | 언제 갈까? | "아직 담은 장소가 없어요" + 어디 갈까?에서 모으기 / 랜덤 뽑기 |
| 후보함 비어 있음 | 어디 갈까? 하단 막대 | "마음에 드는 곳을 ♡로 담아보세요" |
| 일정 없음 | 날씨 대안 | 날짜별 날씨는 보여주고 "일정을 넣으면 대안을 알려드려요" |
| 그날 장소 0\~1곳 | 어떻게 갈까? | "이동할 구간이 없어요" + 언제 갈까?로 |
| 취향 테스트 안 함 | 어디 갈까? | 이름순 + "1분 취향 테스트로 맞춤 순서 켜기" |
| 저장된 여행 없음 | 홈, 도슨트 목록 | 내 여행 카드·내 여행 장소의 이야기 숨김 |
| 지도 불러오기 실패 | 어디 갈까?, 언제 갈까? | 목록만 보여주고 지도 자리에 다시 시도 |
| 경로 실패 | 어떻게 갈까? | 그 구간만 "경로를 불러오지 못했어요" + 카카오맵에서 열기 |
| 날씨 실패·예보 전 | 날씨 대안 | 그날 카드에 "예보 전" 또는 다시 시도 |
| 근거 부족 장소 | 도슨트 | 해설 대신 공공데이터 소개 원문만, "소개만 있어요" |
| 한국어 음성 없음 | 도슨트 듣기 | "이 기기에서는 듣기를 지원하지 않아요" |
| 없는 장소 주소 | 도슨트 상세 | 안내 + 도슨트 목록으로 (404) |
| 기간 축소 | 언제 갈까? | 사라진 날짜 장소를 날짜 없는 곳으로 옮기고 알림 |

## 8. AI 도슨트 콘텐츠 생성 방식

해설은 근거 자료 안에서만 쓰고, 오픈 전에 장소별로 미리 만들어 저장해 사용자는 기다림 없이 본다(팀 프로젝트 명근 님의 근거 기반 설계를 계승).

1. **근거 모으기** (장소마다): TourAPI 장소 설명, 국가유산청 근처 유산(반경 1km 이내), 부산근현대역사관 아카이브 기록·옛 사진, 부산테마여행정보.
2. **해설 만들기**: AI에게 근거만 주고 "자료에 없는 연도·인물·전설은 만들지 말 것, 근거가 없으면 '관련 내용이 없어요'"로 지시. 결과는 한 줄 요약, 역사와 문화, 동네의 특징, 방문 전 알아두기, 현장 관람 포인트 2\~3개. 문장마다 근거 번호.
3. **들려주기 원고**: 근거 번호·괄호를 뺀 말하는 문체 원고를 따로 만든다("지금 서 계신 곳은...").
4. **저장**: 장소별 해설 묶음 + 생성일. 월 1회 다시 만든다(근거가 바뀔 수 있음).
5. **검수**: 오픈 전 대표 장소부터 사람이 읽어보고, 근거와 다른 문장은 고치거나 지운다.

**듣기 음성**

- 국가유산에 해당하는 장소: 국가유산청 나레이션 API의 공식 음성 해설 우선(이용 조건 확인 필요).
- 그 외: 브라우저 내장 음성. 기기마다 목소리가 달라서, 어색하면 다음 버전에 음성 파일을 미리 만든다.

**하지 않는 것**: 뉴스 기사 요약, 근거 없는 거리·시간 언급(거리는 좌표로 계산), 사용자 질문에 즉석 답변(다음 버전).

**키 관리**

- 카카오 지도 키만 화면 코드에 들어간다(도메인 등록으로 보호).
- 나머지 키는 전부 서버의 `.env`에만 두고 절대 커밋하지 않는다. OpenAI 키 유출은 곧바로 비용이 된다.

**서버에 저장해 두는 것**: 장소 목록(월 1회 갱신), 도슨트 해설 묶음(월 1회), 경로 결과(같은 구간 재사용), 날씨·최근 소식(짧게만).

## 10. 반응형·접근성·공통 UI 원칙

휴대폰을 먼저 설계하고 데스크톱으로 넓힌다. 기준 폭은 390px(휴대폰)과 1440px(데스크톱).

- **반응형**: 데스크톱의 다단 배치(예: 목록·지도·후보함)는 휴대폰에서 지도 + 아래 서랍 + 하단 고정 막대로 바꾼다. 화면이 옆으로 밀리면 안 된다.
- **누르는 크기**: 모든 버튼·칩·지도 칸은 44px 이상.
- **키보드·화면 읽기**: 끌어서 놓기(순서 바꾸기)는 키보드로도 가능해야 한다. 선택 상태는 aria-pressed / aria-selected, 아이콘만 있는 버튼은 이름(aria-label).
- **움직임 줄이기**: 이 설정이 켜진 사용자는 랜덤 뽑기 연출 등 움직임 없이 결과만.
- **한 화면 한 강조**: 강조 요소는 화면마다 하나(홈은 내 여행 카드). 버튼은 장소당 하나로 줄이고 나머지는 ⋯ 메뉴.
- **공통 조각**: 여행 조건 줄, 날짜 탭, 장소 카드, 일차 고르기 창, 하단 고정 막대는 한 번 만들어 모든 화면에서 같이 쓴다.
- **디자인 기준(미정)**: 지난 논의의 방향은 "흰 여백 + 진한 먹색 글씨 + 포인트 색 하나(부산 바다 청록)". 개발 전에 색·글꼴·둥글기 값을 확정한다.

## 11. 출처 표기와 이용 조건

출처는 공통 하단(푸터)에 모아 적고, 사진·해설·날씨처럼 화면 안의 데이터에는 그 자리에 작은 글씨로 표기한다.

- **사진**: 출처 기관 + 공공누리 유형을 사진 위에 표기. 변경금지 유형은 자르거나 덧칠하지 않는다.
- **AI 해설**: "아래 근거 자료에 있는 내용만으로 AI가 만든 해설이에요 · 생성일" 표기 + 근거 자료 목록.
- **날씨**: "기상청 예보 · 발표 시각 기준".
- **경로**: 카카오맵·카카오모빌리티 표기 규칙 확인 후 적용.
- **최근 소식**: 기사 제목·언론사·날짜만, 원문 링크. 요약 금지.
- **팀원 작업물**: 팀 레포의 이미지 등을 쓰면 시연 때 만든 사람을 밝힌다.
- **상업적 이용 주의**: 광고·유료화를 붙이면 카카오모빌리티 제휴 계약, 공공누리 상업 이용 금지 유형을 다시 검토한다.

## 12. 개발 순서와 수용 기준

공통 여행 정보와 장소 데이터를 먼저 만들고, 화면은 사용 흐름 순서로 붙인다. 각 단계는 아래 체크가 모두 통과해야 다음으로 넘어간다.

1. **준비**: 새 레포, 화면·서버 기본 구조, `.env` 키, 디자인 기준 값
2. **장소 데이터**: TourAPI·부산테마여행정보로 부산 장소 목록 만들기 → 실제 분류 이름 확인 → 취향 분류표·실내/야외 분류표 확정
3. **내 여행 정보 저장소**: 지역·기간, 취향, 후보함, 일정 + 초기화·되돌리기 + 기간 변경 규칙
4. **홈** → 5. **어디 갈까?** → 6. **언제 갈까?**
5. **도슨트 해설 미리 만들기** (근거 수집 → 생성 → 사람 검수) → 8. **도슨트 목록·상세** (듣기 포함)
6. **취향 테스트·랜덤 뽑기** → 10. **어떻게 갈까?·날씨 대안**
7. **빈 상태·오류 화면, 출처 표기, 공유 미리보기(링크 제목·이미지)** → 12. **배포**

**수용 기준 (QA 체크리스트)**

- [ ] 홈에서 구를 고르고 시작하면 어디 갈까?가 그 구 범위로 열린다
- [ ] 아무것도 안 고르고 시작하면 부산 전체로 열린다
- [ ] 어느 화면에서 후보함에 담아도 다른 모든 화면에 바로 반영된다
- [ ] 같은 장소를 두 날짜에 넣을 수 없다
- [ ] 기간을 줄이면 사라진 날짜의 장소가 날짜 없는 곳으로 옮겨지고 알림이 뜬다
- [ ] 여행 초기화 후 되돌리기를 누르면 모든 정보가 복구된다
- [ ] 도슨트 문장의 근거 번호를 누르면 원문이 보이고, 근거 없는 부분은 없다고 표시된다
- [ ] 듣기가 지원되지 않는 기기에서 안내 문구가 뜬다
- [ ] 날씨 대안은 바꾸기를 누르기 전에는 일정을 바꾸지 않는다
- [ ] 390px 화면에서 옆으로 밀리는 곳이 없고 모든 버튼이 44px 이상이다
- [ ] 키보드만으로 주요 흐름(시작 → 담기 → 날짜 넣기 → 순서 바꾸기)이 가능하다
- [ ] API 하나가 실패해도 나머지 화면은 정상 동작한다
- [ ] 커밋 기록에 키(.env)가 없다

## 13. 열려 있는 결정과 리스크

개발 전에 닫아야 할 결정은 분류표 두 개와 디자인 기준이고, 가장 큰 리스크는 해설의 정확성과 그림 제작 시간이다.

**정해야 할 것**

- [ ] 취향 유형 → 장소 분류 규칙표 (TourAPI 실제 분류 이름 확인 후)
- [ ] 실내/야외 분류 규칙표 (날씨 대안용)
- [ ] 디자인 기준: 색·글꼴·둥글기 값
- [ ] 홈 첫 문구 (도슨트 중심으로)
- [ ] "이번 주 부산 이야기" 고르는 기준과 담당 (주말 버전은 고정 목록)
- [ ] 카카오맵 대중교통·도보 경로 API 무료 쿼터 숫자 확인
- [ ] 국가유산청 나레이션·이미지 이용 조건 확인
- [ ] 방문 기록 도구를 넣을지 (일정까지 만든 사람 비율 측정)

**리스크와 대응**

| 리스크 | 대응 |
| --- | --- |
| AI 해설이 근거와 다른 내용을 말함 | 근거 안에서만 생성 + 근거 번호 + 오픈 전 사람 검수 |
| 이야기할 근거가 부족한 장소가 많음 | "소개만 있어요"로 구분, 이야기 있는 장소 중심으로 노출 |
| 그림 24장 제작 지연 | 글자 카드로 먼저 열고 그림만 교체 가능하게 |
| API 한도 초과·장애 | 서버 저장·재사용, 실패 시 부분 안내 |
| 계정이 없어 기기를 바꾸면 여행이 사라짐 | 주말 버전은 안내만, 다음 버전에서 공유 링크 |
| 팀 프로젝트 기반 작업의 오해 | 시작 전 팀에 "완성형 시연 버전 실험" 공유, 시연 때 팀원 기여 표기 |
