# 날씨 API

`GET /api/weather`에서 부산 대표 격자 또는 저장된 장소의 단기예보를 조회한다. API허브의 `getVilageFcst`를 서버에서만 호출하며 `.env`의 `KMA_APIHUB_AUTH_KEY`를 사용한다. 브라우저에 키·인증 URL·외부 오류 본문을 전달하지 않는다.

## 요청

| 조건 | 동작 |
| --- | --- |
| `placeId` | `data/places/places.json`의 장소 ID. 생략하면 부산 대표 격자 `98,76` |
| `startDate` | `YYYY-MM-DD`. KST 기준 오늘 이후. 기본은 내일 |
| `days` | 시작일 포함 1~14일. 기본 3일 |

예: `/api/weather?placeId=126081&startDate=2026-10-25&days=14`.

잘못된 날짜(2월 30일 포함)·지난 날짜·중복/미지원 조건·잘못된 기간은 400, 없는 장소는 404다. 날짜·기간·장소 확인을 먼저 하므로 이런 요청에는 외부 API를 호출하지 않는다.

대표 격자는 부산 전체의 날씨가 같다는 뜻이 아니다. 장소를 고르면 해당 좌표를 기상청 공식 수식으로 5km 예보 격자로 바꾼다. 날씨 화면에서 장소별 차이를 다루려면 `placeId`를 전달해야 한다. 실시간 현재 날씨가 아니라 발표시각 기준의 예보다.

## 응답

상위 필드: `location`(장소명·ID·격자), `source`(기상청·안내 링크), `issuedAt`(실제 사용한 발표시각, +09:00), `fetchedAt`(서버 수집시각), `days`(날짜별 배열).

| 날짜별 필드 | 의미 |
| --- | --- |
| `date` | 해당 날짜 |
| `status` | `forecast` 예보 있음 / `not-forecast` 최신 응답의 예보기간 이후 / `unavailable` 기간 안 자료 누락·결측 |
| `condition` | `clear`, `cloudy`, `overcast`, `rain`, `snow`, `rain-snow`, `unknown` |
| `precipitationExpected` | PTY 기준 강수 예보가 있으면 true. 조회 시각 모두 강수 없음이면 false. 판단 불가면 null |
| `maxPrecipitationProbability` | 받은 시각 중 최대 POP(%). 없으면 null |
| `minTemperature`, `maxTemperature` | 공식 TMN/TMX 값(℃). 없으면 null. 남은 시간대의 기온으로 하루 최저·최고를 만들어내지 않음 |
| `periods` | 받은 시각별 `time`, `temperature`, `precipitationProbability`, `precipitationType`, `sky` |

날짜 요약은 **반환된 시각들**을 기준으로 한다. 오늘 남은 시간대만 있거나 먼 날짜가 3시간 간격일 수 있으므로 `periods`를 함께 확인한다. 하루 중 비·눈이 한 번이라도 예보되면 강수로 표시하며, 강수가 없을 때는 반환 시각 중 가장 흐린 하늘 상태로 요약한다. PTY/SKY 일부가 빠지면 맑음으로 단정하지 않고 `unknown`으로 남긴다. POP 최대값은 그날 전체의 강수확률을 새로 계산한 값이 아니다.

강수형태(단기 PTY)는 없음 0, 비 1, 비/눈 2, 눈 3, 소나기 4이며, SKY는 맑음 1·구름많음 3·흐림 4다. ±900 이상인 결측이나 범위를 벗어난 숫자는 null로 남긴다. 기온·강수확률이 해상 마스킹으로 없을 수도 있다.

API는 브라우저 여행 정보나 일정을 읽거나 변경하지 않는다. 일정 교체는 화면에서 사용자가 선택할 때 수행한다.

## 발표·전체 페이지·캐시·오류

- 공식 발표시각은 KST 02/05/08/11/14/17/20/23시이며 API 제공시각인 발표 10분 뒤부터 최신 발표를 선택한다. 자정 이전 날짜도 함께 계산한다.
- 최신 발표가 공식 `NO_DATA`(03) 또는 totalCount 0이면 직전 발표를 한 번 조회한다. 응답에는 실제로 사용한 발표시각을 적는다. 일반 통신·인증 오류를 예보 전으로 바꾸지 않는다.
- `numOfRows=1000`으로 호출하되 `totalCount`까지 페이지를 모두 받는다. 페이지 수·식별자·중복·요청 격자/발표가 일치하는지 확인하고, 중간에 끊긴 응답은 성공으로 저장하지 않는다. 상한은 10페이지/10,000건, 페이지당 타임아웃은 8초다.
- 검증이 끝난 성공 응답만 격자·발표별로 **5분간 서버 프로세스 메모리**에 저장한다. 같은 자료를 요청하는 동시 요청은 합친다. 최대 64개이며, 서버리스 인스턴스가 새로 생기면 캐시는 비어 있을 수 있다. 영구 캐시·DB는 사용하지 않는다.
- 예보기간을 ‘항상 며칠’로 고정하지 않고 받은 자료의 날짜로 결정한다. 이후 날짜는 `not-forecast`, 기간 안 누락은 `unavailable`로 구분한다.
- 외부 HTTP/인증/응답 형식/타임아웃 오류는 HTTP 502 `WEATHER_UNAVAILABLE`, 키 미설정은 503 `WEATHER_NOT_CONFIGURED`다. 400/404도 `{ error: { code, message } }` 형식이다. 외부 오류를 캐시하지 않으므로 다시 요청할 수 있다.
- HTTP 응답은 모두 `Cache-Control: no-store`다. 검증 전 HTTP 200 오류 본문이 프레임워크 캐시에 남지 않도록 외부 fetch도 `cache: no-store`로 호출하고, 검증 후의 자료만 위 메모리 캐시에 넣는다.

- [공식 API 활용가이드 260623](https://apihub.kma.go.kr/getAttachFile.do?fileName=%EB%8B%A8%EA%B8%B0%EC%98%88%EB%B3%B4%EC%A1%B0%ED%9A%8C%EC%84%9C%EB%B9%84%EC%8A%A4_API%ED%99%9C%EC%9A%A9%EA%B0%80%EC%9D%B4%EB%93%9C_260623.docx): 발표·제공시각, SKY/PTY/POP/TMN/TMX, 결측, Lambert 변환 C 예제 확인. 반경 6371.00877km, 격자 5km, 표준위도 30/60°, 기준경위도 126/38°, x0=42/y0=135에 1부터 시작하는 격자 보정을 적용한다. 별도 좌표 변환 API는 활용신청 미승인(403)이어서 호출에 의존하지 않는다.
- 실제 17시 발표의 부산 `98,76` 응답은 HTTP 200·결과코드 `00`·총 1,052건으로 페이지 나누기를 확인했다.
- 빌드된 서버에서 20시 발표의 부산 `98,76`과 해운대해수욕장 `99,75`를 조회했다. 2026-10-25부터 14일 중 10-29까지 5일은 예보, 이후 9일은 예보 전으로 반환됐다. 같은 요청의 `fetchedAt`이 유지돼 캐시 재사용도 확인했다. 이 내용은 검증 시점 기록이며 현재 예보로 화면에 고정해 쓰지 않는다.
- 실제 HTTP 400/404, 기존 장소 API 200 확인. 테스트 80개·린트·빌드 통과. 발표 경계·날짜·격자·강수·결측·전체 페이지·캐시·실패 비저장·키 비노출을 검증했다. 이번 작업은 서버 기능만 변경해 휴대폰/데스크톱 화면 검사는 해당 없음.
