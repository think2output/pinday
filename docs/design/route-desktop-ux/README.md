# PC 경로 화면 구조 재검토

2026-10-25. **사용자가 A안을 채택했고 `feat/route-desktop-a`에서 실제 화면에 반영했다.** 아래는 구조 선택 당시 시안 기록이다. 최신 실제 화면·검증은 `docs/ROUTE_QA.md`, 사진은 `docs/design/route-ux/qa-a-*.png`.

## 사용자 흐름

1. 오늘 어디서 어디로 움직이는지 훑는다.
2. 확인할 구간을 선택한다.
3. 그 구간의 시간·수단·승하차를 확인하고 필요하면 수단을 바꾼다.
4. 현장 길안내는 카카오맵에서 연다.

같은 화면에서 모든 구간에 같은 조작·안내가 반복되던 것을, 전체 개요와 한 구간의 확인으로 나눈다. 설명 창은 선택 전후 같은 자리에 있어 시선이 덜 움직인다. 모든 이동수단을 자동 비교해 ‘빠르다/추천’으로 표시하지 않는다.

| 안 | 먼저 보는 것 | 구간 선택 | 장점 | 주의 |
| --- | --- | --- | --- | --- |
| A (권장) | 위쪽 가로 하루 동선 | 장소 사이 시간 버튼 | 여행 순서와 선택 구간이 연결됨. 지도 로드 실패에도 조작 가능 | 장소가 많으면 가로 이동. 이전/다음·선택 구간 수·자동 스크롤 필요 |
| B | 큰 지도 | 지도 위 구간 버튼, 오른쪽 선택 상자 | 지역 간 거리를 중심으로 탐색하기 좋음 | 구간이 겹치면 지도 표식이 복잡해짐. 많은 장소·지도 실패 때 선택 상자 의존 |

A의 추천 이유는 여행 순서를 따라 각 구간을 확인하는 흐름과 잘 맞고, 장소가 많거나 지도가 실패해도 같은 방식으로 쓸 수 있어서다. B를 실제 구현하려면 좌표 없는 구간·겹치는 경로·표식 충돌까지 해결해야 한다. 현재 B의 모형 지도 버튼은 첫 3구간 배치만 보여주며, 12곳 전체 표식 배치를 검증한 것이 아니다.

## 확인·재현

- 미리보기: `node scripts/preview-route-desktop.mjs` → `http://127.0.0.1:3102/?v=a` 또는 `?v=b`.
- 사진과 동작 확인: `node scripts/preview-route-desktop.mjs --capture`.
- 확인: 두 안의 구간 선택·이전/다음·수단 변경·환승 단계별 표시·실패 안내, 12곳 중 뒤쪽 구간 선택, 1050/1440px 가로 넘침 없음.
- 날짜는 시안용 고정 예시이고 실제 앱·여행 저장소와 연결하지 않았다. 시간·버스·승하차는 모두 예시, 지도는 이전 QA 사진 일부를 배치 모형으로 사용한다. 선택에 따른 지도 이동·실제 선 강조는 아직 구현하지 않았다. 카카오 경로 API 호출 없음.
- 색 이름과 값은 기존 `tokens.css`에서 읽는다. 디자인 토큰·공통 컴포넌트·여행 저장소는 변경하지 않았다.
- 사진: `a-1440.png`, `b-1440.png`, 각각 `*-transfer-1440.png`, `*-12places-1440.png`.

이후 A안을 실제 데이터·지도에 연결했고 모바일·키보드·많은 장소·오류 흐름을 검증했다. 이 폴더의 HTML과 사진은 선택 당시 모형 자료로 보존한다.
