# 디자인 탐색 기록

## PC 경로 화면 구조 재검토 (2026-10-25)
- 사용자는 PC에서 구간이 반복되는 세로 목록을 선호하지 않는다. A(가로 동선)·B(지도 선택) 비교 후 **A안 채택**. `feat/route-desktop-a`에서 실제 화면 반영·390/1050/1440 검증 완료. 시안 기록 `docs/design/route-desktop-ux/README.md`, 실제 화면 사진 `docs/design/route-ux/qa-a-*.png`.

## 날씨 대안 화면 (2026-10-25)

- 사진: `docs/design/weather-ux/`(390·1440 목록, 고르는 창, 정한 뒤).
- 사용자 피드백: 장소 아래 대안을 펼친 구성은 "사용자를 안 고려하고 쭉 나열한 느낌", "그날 일정에서 바꾸는 부분이 헷갈림", "장소가 많아지면 어떻게 할 건데". 시간대별 비 표시 컨셉은 좋다고 함.
- 고친 원칙: 일정 목록은 장소마다 한 줄, 결정은 목록 밖 한 곳에서 한 장소씩. 맨 위에 결론 한 줄.
- 비교: A 한 줄 목록 + 고르는 창(채택) / B 목록 위 어두운 카드에서 하나씩 넘기기(카드가 늘 화면을 크게 차지해 제외).
- 쓴 방식: 비 맞는 야외 장소만 번호를 먹색 면으로, 나머지는 테두리 번호. 고르는 창의 선택된 장소는 먹색 면 + ✓. 크림 바탕은 쓰지 않음(B안 강조에 시도했다가 뺌).

## 일정·도슨트 화면 (2026-10-25)

- `/schedule`·`/docent`도 홈 기준(흰 바탕·먹색·노란 조명 하나·모서리 0·Wanted Sans/Pretendard)을 적용한 초안. 사용자는 "전체적으로 괜찮다"까지 확인했고 세부는 미확정.
- 쓴 방식: 선택된 날짜 탭·순서 번호·주요 버튼은 먹색 면, 나머지는 얇은 테두리(`ring-line`)나 여백으로 구분. 노란색은 '지금 듣는 중'·근처 추천 제목의 작은 조명 점과 선택 탭의 비 예보 글자에만.
- 사진은 회색 면 위에 `object-contain`으로 원래 비율 그대로(공공누리 3유형 대비). 크림 바탕은 쓰지 않았다(근처 추천 칸에 시도했다가 뺌).
- 검토 거리: 도슨트 휴대폰 하단 고정 칸 높이, 일정의 이동 확인·날씨 확인 버튼 위치(와이어프레임은 하단 고정).

## 탐색 화면 검토 대기 (2026-10-25)

- `/explore`는 기능 연결을 위한 디자인 초안이며 최종 확정 아님. 홈의 색·글꼴·각진 형태만 적용한 상태.
- 사용자가 휴대폰·데스크톱 배치, 목록 밀도, 지도와 목록 비율을 검토하고 조정한 뒤 다음 화면으로 진행한다.
- 2026-10-25 피드백 반영: 단일 장소가 점으로 보이는 것은 지양하고 지도 핀으로 표시. 페이지 아래로 스크롤할 수 없는 고정 높이를 해제. 지도 위 마우스 휠은 페이지 스크롤, 확대·축소는 +/− 버튼으로 제공.

## 컨셉: 핀 조명

PinDay의 "핀"을 두 가지로 겹친다: 지도에 꽂는 핀 + 전시실 작품을 비추는 핀 조명. "부산이라는 전시실에서 내가 고른 곳에 조명이 켜진다."

## 사용자가 좋아한 것 (살릴 것)

- **마우스를 따라다니는 조명**: 블록 지도 위에서 손전등처럼 빛 원이 커서(휴대폰은 누른 자리)를 따라감. 위에서 내려오는 조명이 아니라 **정면에서 비추는** 느낌.
- **구를 누르면 조명이 "탁" 켜짐**: 빛이 퍼지며 살짝 깜빡인 뒤 고정, 핀 아이콘이 꽂힘. 켜진 곳이 생기면 지도 바탕이 한 톤 어두워짐. 움직임 줄이기 설정이면 연출 없음.
- **흰 바탕** (따뜻한 종이색은 싫어함).
- **전시 벽 + 조명 원 (이번 주 부산 이야기)**: 사용자가 보낸 갤러리 사진(벽에 둥근 스포트라이트, 그 안에 사진 여러 장, 아래 이름) 참고. 네모 사진을 둥근 빛 안에 거는 방식이라 공공누리 3유형(변경금지) 사진을 자르지 않아도 된다.
- **기울어진 사진 콜라주 + 핀 꽂힌 지도 조각** (레퍼런스: 인용 카드 앱, komoot).
- **짧은 메인 카피**: "핀을 꽂으면, 이야기가 켜져요" / "부산 어디에 조명을 비춰볼까요?" (홈 첫 문구는 아직 확정 아님)
