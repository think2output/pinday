## 사용자와 일하는 법 (이번 세션에서 배운 것)

- 사용자는 PM, 코딩 초보. **쉬운 말로, 짧게, 결론부터.** 전문 용어·영어 약어를 쓰면 바로 "모르겠다"고 한다.
- **긴 문서를 직접 읽게 하지 말 것.** 검수가 필요하면 에이전트가 대조하고 "장소 | 한 줄 | 상태" 같은 짧은 표 + 정할 것 2~3개로 물어본다. 사용자는 "1번 OK, 2번 빼" 식으로 답한다.
- 정할 게 애매하면 말로 설명하기보다 **실제 화면 시안을 만들어 보여주면** 빨리 결정한다(근처 추천·날씨 대안이 그렇게 정해졌다). 시안은 별도 브랜치에, 화면 사진을 `docs/design/…`에 넣어 링크로 보여주면 바로 연다. 두 안을 표로 비교하면 고르기 쉬워한다.
- **화면은 사용 흐름을 먼저 생각할 것.** 기능을 위에서 아래로 쭉 나열하면 "사용자를 안 고려했다"고 한다. 결론 한 줄을 맨 위에, 목록은 한 줄씩, 결정은 한 곳에서 하나씩. "장소가 많아지면?"을 항상 확인한다.
- "고고", "알아서 해"라고 해도 비용이 드는 일(OpenAI 호출 등)은 **예상 비용을 먼저 말하고 최소로**. 공통 파일 수정은 여전히 먼저 묻는다.
- 일이 끝나면 커밋·push하고 PR 링크를 준다. 병합은 사용자가 한다.

## 화면별 핵심 규칙 (자세히는 각 QA 문서·DECISIONS)

**언제 갈까?**
- 저장은 기존 `tripActions`만. 일차 기준(`days[0]`=1일차), 같은 장소는 하루만, 일정에서 빼도 후보함 유지.
- 탐색 폴더의 `kakao.ts`·`mapCoordinates.ts`·`ConditionsEditor.tsx`를 수정 없이 가져다 씀(사용자 승인). 공통 폴더로 옮기려면 먼저 묻기.
- 끌기는 라이브러리 없이 직접 구현(`DayList.tsx`). 날씨는 예보 전·자료 없음·실패를 '비 없음'으로 바꾸지 않는다(`scheduleModel.ts`).
- 근처 추천: 직선거리 2km 안·아직 안 담은 곳·최대 3곳, 걸리는 시간은 쓰지 않음. "네 덩어리만" 결정의 사용자 승인 예외.
- '날씨 확인'은 `/weather?day=N`, '이동 확인'은 `/route?day=N` 링크. 둘 다 휴대폰에서도 지도 아래(하단 고정 여부는 사용자 검토 대기).
- ⋯ 메뉴 '이야기 보기'는 승인 해설이 있는 곳만 링크.

**날씨 대안**
- 비·눈 예보 날에만 대안. 거리 제한 없이 가까운 실내 3곳, 직선 2km 안 이야기 있는 곳 우선, 웰니스는 맨 뒤, 일정에 있는 곳 제외(사용자 결정).
- 목록은 장소마다 한 줄, 결정은 [바꾸기]로 여는 고르는 창에서만(사용자 선택 A안). 교체는 '이 장소로 바꾸기'를 눌러야만(`replaceInDay`). '바꾼 장소'·'그대로' 표시와 되돌리기는 탭의 sessionStorage에만(`swapMemo.ts`) — 저장소 수정 없음.
- 시간별 비 막대는 받은 시각의 강수형태만, 빈 시각을 '비 없음'으로 채우지 않는다. 일차 지정이 없으면 첫 비 오는 날을 연다.
- 일정 화면의 `scheduleModel.ts`·`useScheduleWeather.ts`를 수정 없이 가져다 씀.

**AI 도슨트**
- 화면은 `publishable: true` + `humanReview.status: approved` + 자동 검사 0건인 해설만 읽는다. 미검수 근거(충분 후보 83곳 포함)를 이야기 있는 장소로 표시하지 않는다.
- 검수 방식(사용자 승인): AI가 문장별 원문 대조 → 짧은 표로 보고 → 사용자 승인. 한 문장뿐인 해설은 공개하지 않는다(해운대해수욕장 비공개).
- 생성: 기본 미리보기, `--run`일 때만 호출, `--only`·`--budget`, 문서만 `--report`. 승인된 해설은 `--force` 없이 덮어쓰지 않는다. 모델 `gpt-6-luna`. OpenAI 선불 $5 중 지금까지 약 $0.002 사용.
- 근거 문단이 짧아 대부분 요약·관람 포인트만 있다. 최근 소식·국가유산청 공식 음성은 이용 조건 확인 전이라 없음. 듣기는 브라우저 내장 음성.

## 사용자 확인이 필요한 것

- `/schedule`·`/docent` 세부 디자인(사용자는 "전체적으로 괜찮다"까지 확인). 도슨트 휴대폰 하단 고정 칸이 높음.
- 실제 휴대폰에서 ⋮⋮ 끌기 감도, 도슨트 듣기(기기별 한국어 목소리).
- 실제 휴대폰에서 날씨 대안 고르는 창 확인.
- 기존 화면(`/schedule`·`/explore`)도 같은 기준("쭉 나열" 여부)으로 다시 볼지.
- 헤더 메뉴 정리는 메인 메뉴를 다 만든 뒤에(사용자). `/route`는 이제 구현돼 404가 아니다. 공통 `SiteHeader` 수정이라 그때도 먼저 묻기.
- 홈 이야기 카드에서 승인된 도슨트로 연결할지(지금은 듣기·전체 보기 숨김 상태).

## 디자인·구현 주의 (계속 유효)

- `src/styles/tokens.css` 이름만 사용. 제목 Wanted Sans·본문 Pretendard, 모서리 0, 흰 바탕·먹색·노란 조명 하나. 둥근 카드·크림 바탕·구분선 남발·영문 모노 라벨·형광펜 금지. 홈 상단 큰 내 여행 카드 금지. `docs/design/README.md`.
- `useTrip()`을 쓰는 화면은 `<Suspense>`로 감싸야 빌드된다. 날짜 표시는 브라우저에서 그린 뒤(`mounted` 확인).
- Next.js 16.4.3(cacheComponents 켜짐)·React 19.3.0. 작성 전 `node_modules/next/dist/docs/` 확인. 동적 주소는 `generateStaticParams`가 1개 이상 돌려줘야 한다. AGENTS.md의 Next 안내 블록을 지우지 않는다.
- vitest에는 `@/` 경로 별칭이 없다. 테스트 대상 파일은 상대 경로로 import.
- 반송공원(2907087) 원본 좌표가 부산 밖. 추측해 고치지 말고 지도·거리 계산에서만 제외.
- 사진 공공누리 3유형은 자르거나 기울이거나 덧칠하지 않는다(`object-contain`). 출처·유형 표시.
- 브라우저 확인은 별도 Chrome 프로필(`--user-data-dir`)로 한다. PowerShell은 한글 인자를 깨뜨리니 확인 스크립트는 파일로 써서 `node`로 실행.
- `.vscode/`는 사용자 개인 설정(커밋 제외). `.env`·키는 출력·커밋 금지(있는지 여부만 확인).
