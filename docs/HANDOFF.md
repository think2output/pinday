## 가장 먼저 알아둘 것

- 다음 구현은 **언제 갈까? `/schedule`**. 후보를 날짜별로 배치하는 화면과 탐색 화면의 일정 배치 연결을 만든다. 상세 범위는 아래와 `docs/NEXT_AGENT_PROMPT.md`.
- 마지막 구현 검증: **테스트 88개·린트·빌드 통과**. Chrome 390px·1440px에서 실제 카카오 지도·핀·묶음 핀·검색·후보 저장·페이지 스크롤·키보드·터치 확인. 기록: `docs/EXPLORE_QA.md`, 홈·내 여행: `docs/HOME_QA.md`.
- 사용자는 핀·스크롤 개선 후 대체로 괜찮다고 하고 커밋·push를 요청했다. **탐색 디자인 전체가 최종 확정된 것은 아니다.** 기능 구현 완료와 디자인 확정을 구분할 것.
- 로컬 확인 주소는 **http://localhost:3000/**. `127.0.0.1:3000`에서는 카카오 지도 오류가 재현됐고, 사용자가 localhost로 바꾼 뒤 지도 표시를 확인했다.
- 홈 상단의 큰 흰 '내 여행 카드'는 사용자가 거절해 제거했다. 여행 요약·초기화·되돌리기는 **별도 `/trip` 페이지**에 둔다. 홈에 다시 올리지 말 것. 상단 내 여행 버튼도 `/trip`으로 연결돼 있다.

## 다음 작업: 언제 갈까? `/schedule`

기준: `docs/기획서.md` **6-5·7·10·12장**, `docs/DECISIONS.md`, `docs/wireframes/When-desktop.dc.html`, `When-mobile.dc.html`, `When-mobile-picker.dc.html`. 와이어프레임은 배치·요소·동작을 따르고 색·글꼴은 확정 디자인 값을 쓴다.

1. **네 영역**: 날짜 탭 → 그날 일정 → 아직 날짜 없는 곳 → 그날 지도. 후보함이 비면 탐색에서 모으는 빈 상태.
2. 날짜 없는 곳의 '+ N일차에 넣기'는 **지금 선택한 날에 바로 추가**. 매번 일차 선택 창을 띄우지 않는다.
3. 장소 행동은 ⋯ 메뉴에 모으기. 다른 날로 옮기기·일정에서 빼기. 순서 바꾸기는 끌기와 키보드로 모두 가능해야 한다.
4. 그날 지도에 순서 번호와 점선 연결. 실제 길찾기 경로라고 표현하지 않는다. 지도 실패·잘못된 좌표에도 목록과 편집은 동작해야 한다.
5. 날씨 API 계약에 따라 날짜 탭 강수 표시 연결. 예보 전·결측·오류를 맑음으로 처리하지 않는다. 대표 지점 예보면 그 범위를 명확히 표시하고, 날씨 장애가 일정 편집을 막으면 안 된다.
6. 구현 후 `/explore`의 비활성 '날짜에 배치하기 · 준비 중'을 실제 `/schedule` 이동으로 연결. `/trip` 이어서 계획하기와 헤더 일정 메뉴에서 들어오는 흐름도 확인.
7. 이동 확인·날씨 확인의 목적 화면은 아직 미구현. 준비 중으로 안내하고 잘못된 화면으로 이동시키지 않는다. 도슨트 해설도 없으므로 이야기·듣기 링크를 임의로 활성화하지 않는다.

**여행 저장소를 재구현하지 않는다.** `unscheduled()`·`dayOf()`·`summary()`, `tripActions.addToDay`·`moveToDay`·`removeFromSchedule`·`reorderInDay`를 먼저 읽고 사용한다.
- 일정은 날짜 문자열이 아닌 **일차** 기준: `days[0]` = 1일차. 출발일 변경 시 일정 유지.
- 일정에 넣어도 후보함에 남고, 동일 장소는 두 일차에 동시에 들어갈 수 없다.
- 일정에서만 빼면 후보함에 남는다. 후보함에서 빼면 일정에서도 빠진다.
- 기간 축소로 없어진 일차의 장소는 날짜 없는 곳으로 돌아오고 알림이 표시돼야 한다. 선택 중인 일차가 사라지는 경우도 확인.
- 현재 실제 브라우저 사용자 저장 정보를 테스트 데이터로 덮어쓰지 말고 별도 프로필을 사용한다.

공통 파일(저장소·tokens.css·공통 컴포넌트)의 변경·공통 코드 추출이 필요하면 **먼저 사용자에게 확인**한다. 이전 헤더 링크 수정 승인은 다른 공통 파일의 포괄적 수정 승인이 아니다.

## 디자인·구현 주의

- `src/styles/tokens.css` 이름만 사용. 화면 코드에 색 코드 직접 추가 금지. 제목 Wanted Sans·본문 Pretendard, 모서리 0, 흰 바탕·먹색·노란 조명 하나.
- 둥근 카드·크림 바탕·구분선 남발·영문 모노 라벨·형광펜 금지. 구체적인 선호는 `docs/design/README.md`. 홈 상단 큰 여행 카드 금지.
- `useTrip()`은 오늘 날짜를 읽는다. 이 훅을 쓰는 새 화면은 **`<Suspense>`로 감싸야 빌드가 된다** (`src/app/page.tsx`, `src/app/explore/page.tsx` 참고).
- Next.js 16.4.3·React 19.3.0. 작성 전 관련 `node_modules/next/dist/docs/`를 읽는다. Next dev가 쓰는 AGENTS.md 안내 블록을 지우지 않는다.
- 카카오 지도 로더·좌표 보호 구현은 탐색의 `kakao.ts`, `PlacesMap.tsx`, `mapCoordinates.ts`를 참고하되, 일정 지도는 순서 번호·점선이라는 다른 요구가 있다. 기존 탐색 동작을 바꾸지 않도록 한다.
- **반송공원(2907087)** 원본 좌표가 부산 밖. 탐색은 목록·후보 담기를 유지하고 지도 핀·자동 확대만 제외. 원본을 추측해 고치지 말고 일정 지도도 이 오류로 범위가 망가지지 않도록 한다. 정확한 좌표 보완은 별도.
- 사진 공공누리 3유형은 자르거나 기울이거나 덧칠하지 않는다. 출처·이용 유형 표시. 지역 비교는 전체 이름과 정확히 비교(서구/강서구 혼동 금지).
- 테스트·린트·빌드, 390px·1440px, 키보드·터치와 관련 QA를 완료하고 사용자가 **localhost 실제 화면**에서 확인할 수 있게 한다. 기능 구현과 디자인 확정 여부를 따로 보고한다.

- `/schedule`, `/route`, `/weather`, `/docent`, `/taste` 화면, 랜덤 뽑기. 탐색의 일정 배치·이야기 필터·취향 테스트는 현재 준비 중.
- 홈 첫 문구, '이번 주 부산 이야기' 선정 기준, 지도 나머지 13칸 그림. 글꼴 분할 다운로드 검토.
- 도슨트 사람 검수·생성: `data/docent/README.md`, `docs/docent-evidence-review.md`, `data/docent/reviews/representative-2026-10-24.json` 참고. 충분 후보 83곳을 공개 이야기로 취급하지 않는다. 생성 시 선택 문단·제외/재검수/미검수 상태·원문 해시를 적용해야 한다.
- 25의용단(126814) TourAPI/국가유산청 설명 충돌, 백제병원 연혁·석당박물관 상세 연결 검수, 부산근현대역사관 아카이브 승인 후 보완 필요. 주변 유산은 nearby-only·단순 언급 mentioned-only 구분.
