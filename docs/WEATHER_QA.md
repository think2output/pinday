# 날씨 대안 구현·확인 — 2026-10-25

브랜치 `feat/weather` (← `origin/main` `20ac311`, PR #13 병합 후). 기획서 6-7, 와이어프레임 `Weather-*`·`Empty-weather`. 화면 사진 `docs/design/weather-ux/`.

## 사용자 결정

- 실내 대안은 **거리 제한 없이** 가까운 실내 장소 3곳("멀어도 외부보다 실내가 낫다"). 웰니스(요가·스파 등)는 맨 뒤로.
- 실내·야외가 함께 있는 곳도 실내에서 지낼 수 있으면 실내로 친다. 장소별 예외 28곳 추가(`docs/분류표.md`, `scripts/build-places.mjs`의 `INDOOR_IDS`). 실내 79 → 107곳.
- 날씨는 일정 화면과 같은 부산 대표 지점 하나로 본다.
- 화면 구성은 시안 비교 끝에 **A안(한 줄 목록 + 고르는 창)**. 처음 구현(장소 아래 대안 3곳 펼침)과 1차 시안(장소마다 추천 하나 펼침)은 "쭉 나열돼 헷갈리고 장소가 많아지면 길어진다"는 피드백으로 버림. B안(하나씩 정하는 어두운 카드)은 비교 후 채택 안 함.

## 화면 구성 (위에서 아래)

1. 제목·조건 줄(조건 바꾸기 창).
2. **여행 요약 한 줄**: "1일차 10.26 (월)에 비 예보가 있어요" + "그날 야외 장소 N곳, 실내로 바꿀지 정해보세요". 비 소식 없음·예보 전·실패·지난 여행도 각각 문구.
3. 날짜 탭: n일차·날짜·하늘(비·맑음·예보 전 등). 주소에 `?day=N`이 없으면 **첫 비 오는 날**을 연다.
4. 그날: 하늘·강수확률(또는 최저/최고 기온) → **시간별 비 막대**(받은 예보 시각마다 한 칸, 비=먹색·없음=옅은 칸·자료 없음=빈 테두리) + "0시~8시에 비 예보가 있어요. 9시부터는 비 소식이 없어요."
5. **그날 일정**: 장소마다 한 줄(번호·이름·지역·분류·상태). 비 오는 날 야외 장소만 번호가 먹색이고 '☂ 야외' + [바꾸기]. 실내는 '실내', 바꾼 곳은 '실내로 바꿈 · 원래 ○○' + 되돌리기, 그대로 두기로 한 곳은 '야외 · 그대로' + 다시 정하기. 제목 옆 "비 맞는 야외 N곳" / "모두 정했어요".
6. **[바꾸기] → 고르는 창**(휴대폰 아래에서 올라옴, 데스크톱 가운데): "광안리해수욕장 대신 어디 갈까요?" + 비 시간 → 실내 3곳 중 하나 선택(첫 곳 미리 선택, 직선거리·분류·이야기 있음, 이야기 있으면 ▶ 도슨트 링크) → [이 장소로 바꾸기] / [그대로 갈게요] / [닫기].

## 동작 규칙

- 교체는 고르는 창에서 '이 장소로 바꾸기'를 눌러야만, 기존 `tripActions.replaceInDay`로(날짜·순서 유지, 새 장소는 후보함에도 추가).
- 되돌리기: 원래 장소로 다시 바꾸고, 바꿀 때 후보함에 새로 들어갔던 장소면 후보함에서도 뺀다. 원래 장소가 그새 다른 날에 들어갔으면 되돌리지 않고 안내.
- '바꾼 장소'·'그대로' 기억은 여행 저장소를 고치지 않으려고 이 탭의 sessionStorage에만 둔다(`swapMemo.ts`). 창을 닫으면 표시·되돌리기는 사라지고 바뀐 일정은 남는다(화면에 안내).
- 대안 고르기(`weatherModel.ts`의 `indoorAlternatives`): 실내·좌표 정상·이미 일정에 없는 곳, 직선 2km 안 이야기 있는 곳 → 일반 → 웰니스 순, 같은 묶음은 가까운 순, 최대 3곳.
- 시간별 비(`rainTimeline`): 받은 시각의 강수형태(PTY)만 쓰고, 빈 시각을 '비 없음'으로 채우지 않는다. 마지막 비 시각 뒤가 모두 비 없음일 때만 "N시부터는 비 소식이 없어요".
- 예보 전·자료 없음·강수 판단 불가·불러오기 실패·지난 날짜는 각각 따로 표시하고 맑음이나 '비 없음'으로 바꾸지 않는다. 이때는 [바꾸기]를 보여주지 않는다.
- 빈 상태: 일정이 하나도 없으면 요약·날씨 탭은 보여주고 "일정을 넣으면 대안을 알려드려요" + 후보 있음 → 언제 갈까?, 없음 → 어디 갈까?. 그날만 비었으면 "이 날은 아직 일정이 없어요".
- 반송공원(2907087)처럼 좌표가 잘못된 장소는 고르는 창에서 "지도 위치를 확인할 수 없는 장소라…"(그대로 갈게요만). 실내 후보에서도 제외.
- 언제 갈까?의 '날씨 확인 · 준비 중'을 `/weather?day=지금 일차` 링크로 교체(위치는 지도 아래 그대로).
- 날씨 기호는 컬러 이모지 대신 글자 모양(`\uFE0E`). 노란색은 요약의 작은 조명 점과 선택된 비 오는 날 탭의 우산에만.
- 공통 파일(여행 저장소·tokens.css·SiteHeader) 수정 없음. 일정 화면의 `scheduleModel.ts`·`useScheduleWeather.ts`는 수정 없이 가져다 씀.

## 확인 결과

Chrome headless + DevTools Protocol, 별도 임시 프로필, 개발 서버 `http://localhost:3000`, 1440×1000·390×844. 하루 8곳(야외 5곳) 일정으로 확인.

- 테스트 124개(날씨 대안 계산 16개)·린트·빌드 통과.
- 두 폭 모두 가로 넘침 없음, 본문·창 버튼 44px 이상.
- 실제 예보(10.25 2시 발표): 1일차 비 최대 70%, 0시~8시 비·9시부터 비 소식 없음. 2·3일차 구름많음·맑음(검증 시점 기록).
- 바꾸기 창 → 바꾸기: 저장소 1일차 같은 자리 교체·후보 +1, 초점은 그날 제목으로. 그대로 갈게요 → '야외 · 그대로', 다시 정하기 → [바꾸기] 복귀. 되돌리기 → 원래 장소·후보 수 복구.
- 가짜 응답: 모두 맑음이면 [바꾸기] 없음. 날씨 API 502: 다시 시도 버튼, [바꾸기] 없음.
- 일정 없음 빈 상태, 일정 화면 '날씨 확인' 링크(`/weather?day=1`).

## 남은 것
