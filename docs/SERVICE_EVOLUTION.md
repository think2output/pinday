# 기존 PinDay와 현재 버전의 변화

작성: 2026-10-25 · 사용자에게 개선 내용 설명 및 다음 에이전트 인계용

## 비교 기준

- 사용자가 지정한 기존 PinDay: https://pinday-web.vercel.app/. 다른 서비스와의 비교가 아니다.
- 기존 소스: [ohzoohzo/map-5](https://github.com/ohzoohzo/map-5/tree/ba62012f9768bc6d785ce407bf8b8a1ae96e6b9f). README의 배포 주소가 위 주소와 일치한다.
- 기존 배포 홈은 별도 브라우저 프로필로 직접 열어 제목·본문·메뉴를 확인했다. 하위 기능은 위 소스를 검토했으며, 이전 서버의 도슨트 생성·날씨·경로를 이번에 실호출해 재검증한 것은 아니다. 소스 스냅샷이 배포 전체와 정확히 같은 커밋인지는 미확인이다.
- 현재 비교 대상: think2output/pinday의 구현 기준 a8418a7. PR #21로 main(a973334)에 병합된 상태다. 첫 배포 주소는 https://pinday-five.vercel.app/지만 최신 수정의 운영 반영은 확인하지 않았다.
- 사용자는 기존 주소를 ‘팀플하기 전 서비스’라고 지정했다. 당시 시점의 정확한 커밋은 특정하지 못했으므로 아래는 지정 주소와 연결 저장소를 기준으로 한 비교다.

## 핵심 변화

기존 PinDay가 장소를 모아 날짜별 여행을 설계하는 흐름을 중심으로 했다면, 현재 버전은 그 기반 위에 **부산 지역을 둘러보고, 장소의 이야기를 읽고 들은 뒤 내 일정으로 가져오는 경험**을 더 앞에 배치했다.

장소 탐색·후보함·일정·취향 테스트·랜덤 뽑기·날씨 대안·이동 경로·근거 기반 도슨트는 기존 코드에도 있었다. 이들을 모두 새로 만든 기능으로 설명하지 않는다. 기존 팀 작업을 바탕으로 목적·화면·공개 기준을 재정비한 부분과 새로 보강한 부분을 구분한다.

## 무엇을 어떻게 바꿨나

| 항목 | 기존 PinDay에서 확인한 것 | 현재 구현 | 개선 의도 |
| --- | --- | --- | --- |
| 홈의 시작점 | 부산 목적지·날짜·맛집/산책/전시 태그 입력, ‘내 여행 시작하기’, 이용 단계 설명 | 실제 부산 16개 구·군 지도 선택, 구별 승인 이야기 카드, 날짜·시작 흐름 유지 | 부산을 잘 모르는 사람도 지역과 이야기를 먼저 살펴보게 한다. |
| 지역 선택과 표현 | 홈 목적지는 부산 선택 상자, 큰 배경 일러스트 | 실제 해안선·행정 경계, 큰 구의 명소 선화, 구 이름 위 핀 낙하·물결과 노란 조명 | 부산의 위치 관계를 드러내고 선택 결과를 바로 알아보게 한다. 확대·드롭다운은 사용자 요청으로 제외했다. |
| 이야기 진입 | 별도 AI 도슨트 메뉴와 일정의 장소 패널 | 홈 이야기 카드 → 같은 장소 상세, 공개 목록 → 상세 → 읽기·듣기·후보 담기 | 계획 중인 사람 외에도 장소 이야기 자체로 서비스를 시작하게 한다. |
| 도슨트 공개 방식 | 공공 관광정보·국가유산 자료를 모아 요청 기반 AI 해설 생성, 문단별 근거와 출처 표시 | 해설을 미리 생성·저장하고 사람 검수·자동 검사를 통과한 것만 공개, 문장별 근거 확인·브라우저 음성 | 공개 문장을 사전에 대조하고 방문할 때마다 AI 생성에 의존하지 않게 한다. 현재 공개 범위는 6곳이다. |
| 랜덤 뽑기 | 관광지 이름이 슬롯처럼 바뀌고 한 곳을 표시, 페이지 내 3회, 후보 담기 | 승인된 이야기 카드 모달, 포개기→셔플→펼치기, 직접 선택할 때만 횟수 차감, 상세에서 읽기·듣기 | 단순 장소 추첨에서 이야기 발견으로 목적을 바꿨다. 셔플 자체로 횟수를 소비하지 않는다. |
| 취향 테스트 | 별도 화면에서 응답·유형 결과·추천 장소·후보 담기 | 홈에서 5장면 모달, 부산 4유형과 대표 3곳 코스, 고른 날짜에 명시적으로 추가 | 결과를 본 다음 일정에 옮기는 행동까지 이어준다. 기존 일정과 겹치는 장소는 다시 추가하지 않는다. |
| 날씨와 이동 | OpenWeather 3시간 예보, 사용자 선택에 따른 장소 교체, 대중교통·도보·자동차 경로 코드 | 기상청 시간별 예보, 결측/예보 전/오류 구분, 근처 실내 대안·되돌리기. PC 가로 동선에서 구간별 대중교통·도보·환승 확인 | 비에 따른 판단과 실제 이동 구간을 읽기 쉽게 다듬었다. 자동차는 현재 범위에서 빠져 있다. |
| 화면과 사진 | 밝은 바탕, 둥근 카드, 일러스트·장소 사진 | 흰 바탕·먹색·노란 조명, 각진 카드. 홈 글 순서 통일, 도슨트 목록 3:2와 상세 사진 영역 고정 | 카드마다 사진·글 높이가 달라지는 문제를 줄이고 정보 순서를 맞췄다. 변경금지 사진은 자르지 않고 전체를 표시한다. |
| 운영 구조 | React/Vite 화면과 FastAPI 서버를 별도 배포 | Next.js 한 프로젝트, 장소·검수 해설 JSON, 날씨·경로 서버 API | 화면과 서버 변경을 한 저장소에서 관리한다. 유지보수 시간이 실제 얼마나 줄었는지는 측정하지 않았다. |

## 현재 범위와 한계

- 부산 관광지·문화시설 408곳, 실내 107곳. 해설 근거 408곳과 공개 해설 6곳은 서로 다른 숫자다. 모든 장소에서 AI 이야기를 제공하는 상태는 아니다.
- 기존에도 근거 기반 해설과 공유 여행 저장소가 있었다. ‘출처가 없던 AI를 처음 도입했다’, ‘분리된 기능을 처음 연결했다’고 표현하지 않는다.
- 기존 최근 소식 탭·자동차 경로 코드는 현재 버전에 그대로 이어오지 않았다. 공식 음성·최근 소식은 이용 조건 확인 전, 자동차는 후속 범위다. 기능 수가 모든 면에서 늘어난 것은 아니다.
- 맛집·카페·공유·계정·여러 여행·도슨트 질문 답변은 현재 범위 밖이다. 브라우저에 여행 한 개를 저장한다.
- 위 ‘개선 의도’는 설계 목적이다. 이탈률·계획 시간·이용 만족도·응답 속도가 좋아졌다는 실사용 측정 결과는 아직 없다.
- 현재 코드 검증: 테스트 150개·빌드 통과, 린트 오류 0/기존 경고 1. 휴대폰 390px와 PC 1440px 화면 검증 자료는 화면별 QA와 docs/design에 있다. 기존 서비스의 동일 조건 비교 시험을 수행한 것은 아니다.
